## 1. Модель позиции заявки и физика контейнеров

Заявка (`orders`) → объект (`object_id`) + позиции (`order_items[]`). Каждая позиция:
- `action`: `place` (Поставить), `replace` (Заменить), `haul` (Забрать).
- `quantity`: количество контейнеров.
- `section_id`: участок объекта (nullable, `null` = весь объект). См. §4.
- `container_type_id`, `waste_class`: **ЗАГЛУШКА** — см. §5.

**Физика машины** (для расчёта рейсов):
- За рейс ТУДА: ≤ `empty_capacity` пустых контейнеров (вставляются друг в друга, лего). По умолчанию 2, задаётся в каждой машине (`vehicles.empty_capacity`, миграция 023).
- За рейс ОБРАТНО: ≤ 1 полный контейнер.
- `E` (пустых привезти с базы) = Поставить + Заменить.
- `F` (полных забрать с объекта) = Заменить + Забрать.
- **`рейсы = max(ceil(E / empty_capacity), F, 1)`** — на весь объект (участки НЕ создают отдельных рейсов).
- Примеры: Поставить 2 → 1 рейс; Заменить 2 → 2 рейса; Забрать 2 → 2 рейса.

Код: `server/src/lib/distribute.js` (`tripsFromCounts`, `tripsForItems`), `server/src/services/orderMetrics.js` (`metricsForOrder`, `emptyCapForVehicle`), фронт `src/lib/orderUi.js` (`containerJob`, `containerJobsBySection`).

## 2. Плашка водителя (ContainerJob)

`src/components/admin/ContainerJob.jsx`. Формат (решения пользователя 2026-06-08):
- Эмодзи однотипная пара: **⬜ пустой / 🟩 полный**. Количество = число эмодзи (если >4 → `🟩×N`).
- Порядок: **«Забрать N»** (полные с объекта = `F`) ПЕРВЫМ, затем **«Забираем с базы N»** (пустые = `E`).
- Если позиции привязаны к участкам — **разбивка по участкам**: на каждый участок мини-плашка `📍 Уч. 58: 🟩 Забрать 1  ⬜ с базы 1`, внизу `Итого: N рейсов`.
- Логика разбивки: `containerJobsBySection(o)` в `src/lib/orderUi.js`.
- **Нюанс:** разбивка по участкам видна только там, где есть полный состав позиций (`o.items`): модалка заявки `OrderModal`, превью в `ItemsEditor`. На карточках списков (Review/InWork/Distribution) `listOrders` не отдаёт позиции по участкам — там показывается АГРЕГАТ по заявке. ## 3. Иерархия ГК → заказчик → объект → участок

- `company_groups` (ГК) → `clients.group_id` (nullable, SET NULL) → `objects.client_id` (NOT NULL) → `sections.object_id` (CASCADE).
- Заявка выводит `client_id` ИЗ объекта (`createOrder`, `server/src/services/orders.js`) — рассинхрон невозможен.
- Доверенные лица (`trusted_persons`): принадлежат ЛИБО группе (`group_id`), ЛИБО одиночному клиенту (`client_id`). Пул для клиента: если он в ГК — лица всей группы (`poolForClient`, `routes/trustedPersons.js`). Привязка лицо↔объект/участок — `object_trusted_persons.section_id`.
- Заявка живёт на уровне объекта; участок — на уровне позиции (§4). `orders` НЕ имеет `section_id` (осознанно).
- UI: `src/pages/Clients.jsx` (ГК-карточки → юрлица → объекты → участки + лица). Удаление клиента с объектами блокируется FK (текст подсказки поправлен).

## 4. Участок у позиции (миграция 026)

- `order_items.section_id` nullable FK → `sections`, `ON DELETE SET NULL`. `null` = весь объект.
- Одна заявка на одном объекте может адресовать РАЗНЫЕ участки (напр. «заменить на участках 58 и 62»).
- **Целостность:** сервер при вставке принимает `section_id` только если участок принадлежит объекту заявки, иначе → `null` (`createOrder`/`updateOrder`). Тест: `server/test/orders-create.test.js` («section_id у позиции…»).
- `assembleOrder` отдаёт `section_name` по позиции и `order.object_sections` (список участков объекта для селекта).
- Форма: `src/components/admin/ItemsEditor.jsx` — селект участка в строке, ТОЛЬКО если у объекта есть участки. Проброшено в `OrderModal` (`sections={order.object_sections}`) и `Inbox` (участки выбранного объекта).

## 5. Тип контейнера и класс отходов — ЗАГЛУШКА (миграция 025)

Решение пользователя 2026-06-08: «нигде не используем, в формах не показываем», но легко вернуть.
- `order_items.container_type_id` — снят NOT NULL (миграция 025). `waste_class` и так nullable. **Колонки НЕ удалять** — точка возврата.
- Валидаторы (`server/src/validators/order.js`): оба поля `.nullable().optional()`. Вставка пишет `?? null`.
- Из форм убраны селекты типа/класса (`ItemsEditor`, `OrderModal`, `Inbox`). Позиция = `{ action, quantity, section_id? }`.
- Физические контейнеры (каталог `container_types`, страница Containers, инвентарь объекта, движения при завершении) — ДРУГАЯ сущность, не трогали; там тип остаётся.

## 6. Авто-порядок маршрута (кнопка на «На проверке»)

- `autoRouteOrder(orders)` в `src/lib/orderUi.js`: эвристика — районы держим кучно; доставочные районы (есть Поставить/Заменить) раньше; внутри района доставки раньше заборов; затем по номеру.
- Кнопка «↧ Авто-порядок» в `src/pages/Review.jsx` → проставляет `seq` каждому водителю через `reorder`. Ручное перетаскивание главнее.
- Это round-trip модель (база→объект→база на каждый заезд), межрайонный TSP не делаем — важна группировка.
